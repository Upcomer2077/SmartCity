# 📖 Data Dictionary & Metric Specifications

This document defines the strict data schemas, field types, validation constraints, and payload structures for the SmartCity platform.

---

## 1. Metric Classifications & Validation Bounds

The system processes three distinct core sensor topologies. Any incoming telemetry stream exceeding these operational boundaries must be rejected by the validation layer.

| Metric Type (`Enum`) | Business Definition | Unit of Measure | Valid Range (Min / Max) |
| :--- | :--- | :--- | :--- |
| `TEMP` | Ambient Air Temperature | Degrees Celsius (°C) | `-50.0` to `+60.0` |
| `AIR_Q` | Air Quality Index | AQI (US EPA Standard) | `0.0` to `500.0` |
| `TRAFFIC` | Vehicle Flow Rate | Vehicles per Minute (VPM)| `0.0` to `300.0` |

## 2. Network Data Routing Contracts & Serialization

To enforce sub-millisecond serialization speeds and reduce network bandwidth consumption, the system splits data routing into a highly optimized binary Inbound path and an on-demand reactive Outbound path.

### 2.1. Inbound Ingestion Contract (Edge Transmitter -> Apache Kafka)

The **Transmitter** drains the local SQLite buffer, groups telemetry points by the hardware asset, and compiles them into a binary **Protocol Buffers (Protobuf)** payload. This architecture dramatically cuts down wire overhead by sending the identity key only once per metrics array block.

* **Kafka Topic:** `city.telemetry`
* **Format:** Binary Protobuf Stream

#### Protobuf Schema Specification (`proto/edge_ingestion.proto`)

```protobuf
syntax = "proto3";

package telemetry;

message TelemetryPoint {
    float ts = 1;       // Epoch timestamp float coordinate
    double value = 2;   // Quantifiable scalar dimension metric
}

message DeviceDataBatch {
    string sensor_sn = 1;               // Factory serial number (UUIDv4 string)
    string type = 2;                    // Metric classification ("TEMP", "AIR_Q", "TRAFFIC")
    repeated TelemetryPoint data = 3;   // Array of historical time-series data points
}

message BulkIngestionPayload {
    repeated DeviceDataBatch batches = 1; // Collection of grouped device blocks
}
```

#### Ingestion Execution Flow

1. The **Transmitter** extracts unsent tracking records from SQLite and structures them internally into the `BulkIngestionPayload` layout.
2. The **Ingestor Worker** intercepts the binary frame, unpacks it via compiled Python stubs, and resolves each `sensor_sn` string into the internal `sensor_id` from its relational lookup map.
3. The **Ingestor** executes a high-speed database `UPSERT` operation across all embedded `data` vectors directly into the TimescaleDB hypertables.

### 2.2. Outbound Broadcast Contract (Redis Pub/Sub -> FastAPI -> WebSockets)

This lightweight schema is generated by the **Ingestor Worker** *after* validating bounds and executing the database layer bulk writes. It maintains the batch structure and sends a packed telemetry payload directly downstream to active client rooms.

* **Redis Channel Pattern:** `telemetry:{sensor_id}`
* **WebSocket Payload:** JSON String (Array of Data Points)

```json
{
  "sensor_id": "c3b0a2d1-4e5f-6a7b-8c9d-0e1f2a3b4c5d",
  "data": [
    { "ts": 1781423885.123, "value": 24.5 },
    { "ts": 1781423895.123, "value": 24.8 },
    { "ts": 1781423905.123, "value": 25.1 }
  ]
}
```

#### Field Typing & Optimization Rules

* **`sensor_id`** `(string, UUIDv4, Required)`: The internal surrogate primary key matching `sensors.sensor_sn`. This allows the **WebSocket Manager** to route the frame straight to the specific active room.
* **`data`** `(array, Required)`: A chronological collection of real-time measurements emitted during the last Edge flushing cycle.
  * **`ts`** `(float, IEEE 754)`: Unix Epoch timestamp coordinate for the specific tick.
  * **`value`** `(float, Double Precision)`: Validated scalar telemetry metric payload.
* *Note:* The `type` flag remains excluded to preserve network bandwidth;

## 3. Database Entity Data Catalog

### 3.1. Production Cluster (TimescaleDB / PostgreSQL)

#### Table: `sensors`

Holds the centralized master registry of all verified spatial assets deployed in the ecosystem.

| Column Name | Database Data Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `sensor_id` | `UUID` | `PRIMARY KEY` | Internal database surrogate token for index joins. |
| `serial_number` | `UUID` | `UNIQUE`, `NOT NULL` | Physical hardware asset UUID stamped during factory setup. |
| `created_by` | `INTEGER` | `FOREIGN KEY`, `NULLABLE` | ID of the `admin` user who registered this hardware node. |
| `type` | `VARCHAR / ENUM` | `NOT NULL` | Hardware topology classification (`TEMP`, `AIR_Q`, `TRAFFIC`). |
| `coordinates` | `GEOMETRY(Point, 4326)`| `NOT NULL`, `GiST INDEX` | PostGIS spatial coordinate point storing Longitude & Latitude. |
| `created_at` | `TIMESTAMP` | `DEFAULT NOW()` | Record registration clock tick. |

#### Table: `sensor_hyper_data`

High-volume analytical storage hypertable optimized for time-series logging.

| Column Name | Database Data Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `ts` | `TIMESTAMPTZ` | `PRIMARY KEY (1)` | Time partition coordinate. Dropped after 90 days. |
| `sensor_id` | `UUID` | `PRIMARY KEY (2)`, `FK` | Links telemetry directly to the parent `sensors.sensor_id` asset. |
| `value` | `DOUBLE PRECISION` | `NOT NULL` | The stored scalar floating-point metric value. |

### 3.2. Local Edge Buffer (SQLite inside Simulator)

#### Table: `sensor_data`

Transactional micro-buffer holding un-flushed telemetry chunks locally on disk.

| Column Name | Database Data Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `rowid` | `INTEGER` | `PRIMARY KEY` | Auto-incrementing local row sequence index. |
| `ts` | `FLOAT` | `NOT NULL`, `INDEX (2)`| Local recording timestamp epoch float. |
| `sensor_sn` | `UUID` | `FOREIGN KEY`, `INDEX (1)`| Cascading relation bound to local `sensors.serial_number`. |
| `value` | `FLOAT` | `NOT NULL` | Raw measured data point. |
| `is_delivered` | `BOOLEAN` | `NOT NULL`, `DEFAULT 0`| **[DEPRECATED if using acks=1 direct purge]** State flag. |
