🏙️ Техническое задание
Проект: SmartCity — интеллектуальная платформа мониторинга городской инфраструктуры
1. Общие сведения

Название проекта: SmartCity
Цель разработки: создание веб-платформы, собирающей, обрабатывающей и визуализирующей данные от IoT-датчиков, установленных в городской инфраструктуре (транспорт, экология, температура, освещение и т. д.).

Задачи системы:

принимать и обрабатывать потоковые данные от датчиков в реальном времени;

агрегировать и хранить данные в аналитической БД;

предоставлять REST и WebSocket API для визуализации;

отображать данные и прогнозы в интерактивной панели управления;

обеспечивать масштабируемость, тестируемость и мониторинг всех компонентов.

2. Архитектура системы

Система состоит из следующих подсистем:

2.1. Frontend

Разработан на NuxtJS 3 (TypeScript).

Использует Bootstrap для UI и адаптивности.

Реализует JWT-аутентификацию (доступ к API по токенам).

Использует cookies для хранения refresh-токена.

Реализует WebSocket-подключение для отображения данных в реальном времени.

Отображает:

карту города с активными сенсорами;

графики и статистику;

прогнозы (температура, загруженность, качество воздуха);

панель администратора для управления пользователями.

2.2. Backend

Основной фреймворк — FastAPI (Python 3.11).

Использует:

SQLAlchemy — ORM и слой доступа к данным;

PostgreSQL — основное хранилище данных;

Redis — кеш и очередь короткоживущих данных;

Kafka — потоковая шина данных от IoT-датчиков;

gRPC — взаимодействие с сервисом аналитики (модуль прогнозирования);

WebSocket — отправка данных в реальном времени фронтенду;

Docker + Nginx — контейнеризация и маршрутизация;

pydantic — строгая валидация моделей данных.

2.3. Модуль имитации IoT-датчиков

Отдельный микросервис на Python (python-kafka).

Генерирует данные:

ID сенсора;

тип данных (traffic, temperature, air_quality, light);

значение (float);

координаты и метку времени.

Отправляет данные в Kafka-топики раз в 1–3 секунды.

2.4. Аналитический модуль (gRPC-сервис)

Получает данные от FastAPI;

Использует базовую ML-модель для прогнозирования показателей (например, изменение температуры или загрязнения);

Возвращает результаты в API.

2.5. DevOps и инфраструктура

CI/CD через GitHub Actions;

Развёртывание микросервисов в Kubernetes;

Контейнеризация в Docker;

Prometheus — сбор метрик;

Grafana + Loki — визуализация и алерты;

Nginx — балансировка запросов.

6. CI/CD процесс

При push в ветку main → запускается GitHub Actions pipeline:

установка зависимостей;

запуск unit и integration тестов;

проверка линтинга;

сборка Docker-образов;

деплой в Kubernetes кластер;

smoke-тесты и уведомление о статусе.

При merge PR → автосборка preview-среды для тестирования.

💡 Рекомендация: Использовать PostgreSQL + расширение TimescaleDB — это гибрид: SQL + time-series, идеально для IoT.


Роль gRPC в SmartCity:

gRPC применяется как внутренний протокол между микросервисами. Он нужен, когда:

сервис аналитики отделён от FastAPI;

нужно быстро передавать большие объёмы бинарных данных (например, временные ряды);

нужен строгий контракт API (через .proto).
